# Hya · 声音的层次

本机音频可视化 MVP。Python 服务 + 浏览器 Canvas：先分析整曲，再跟随原曲播放时钟在同一窗口显示六轨：人声、低音、钢琴、吉他音符，鼓点与其他声部能量带。默认使用 Demucs 分轨和 Basic Pitch ONNX 转写；也保留无需第三方依赖的快速音高估计。

## 启动

双击 `启动 Hya.command`，或运行：

```sh
cd /Users/lightscape/Projects/hya
python3 app.py
```

浏览器自动打开带会话 token 的本机地址，并自动加载默认曲目。本机默认曲目为林海《远方的寂静》，音频副本和配置保存在 `outputs/default/`。完成下述预缓存后，打开即可复用分析结果，点击播放开始观察。也可导入其他音频或从「更多设置 → 曲目」选择「自由合成体验」，等待分析完成后播放。示例是合成旋律与和弦，没有真实人声，不适合评估人声分离准确率。关闭终端或 Control+C 停止服务，并取消后台任务。

- 上限：128 MB、10 分钟；模型任务最长运行 30 分钟。
- 默认「分轨分析」使用项目 `.venv/bin/python`，环境与模型准备见 [音频工具说明](docs/AUDIO_TOOLS.md)。现有机器已准备好模型，不需要账号或联网推理。
- 「快速音高估计」调用 macOS `afconvert` + 标准库 FFT，不做分轨。
- 播放器播放原始文件；系统能解码的格式不一定能被浏览器播放，必要时先转换成 WAV / MP3。
- 默认曲目覆盖：`HYA_DEFAULT_AUDIO='/absolute/path/song.flac' python3 app.py`。
- 可选测试入口：`HYA_TEST_AUDIO='/absolute/path/song.wav' python3 app.py`。

## 默认曲目与预缓存

```sh
.venv/bin/python precache.py '/absolute/path/song.flac'
```

已确认是钢琴独奏时，加上 `--piano-solo` 以直接转写原曲。该选项写入默认曲目配置并使用独立缓存，页面仅显示钢琴轨。无参数重新预缓存会复用当前默认曲目的该设置。

完整分析成功后，将音频复制到 `outputs/default/`，原子写入 `track.json`，并验证复制后的文件可以命中缓存。WAV / FLAC 等格式另生成同时间轴的 AAC/M4A 播放副本（160 kbps、faststart），兼容 Safari 并降低传输量；分析仍使用原文件内容命中缓存。不修改原始下载文件。下次启动直接给播放器设置音频地址，使用 HTTP Range 按需读取，同时通过 `GET /default/result` 读取六轨缓存（支持 gzip）。无需下载原曲、重新上传或启动模型任务；缓存缺失时仍可播放，界面提示在电脑上预缓存。无需原始路径；音频、配置和缓存均不提交 Git。省略参数时复用当前默认曲目；尚未配置时尝试查找桌面的 My heart will go on。

本机选用的源文件：`~/Music/QQ音乐/林海-远方的寂静.flac`。如果修改模型、管线代码或依赖锁定文件，需要重新运行上述命令预热新缓存；旧版四轨缓存不能作为六轨结果使用。

## 分轨分析如何工作

1. 上传到仅监听 `127.0.0.1` 的 Python 服务，返回任务 ID。
2. 用音频内容、分析代码、依赖锁定文件及 Demucs 权重/配置生成缓存键；命中则直接读取 JSON。
3. 单个后台工作进程使用 FFmpeg 解码为 44100 Hz 立体声，验证时长。
4. 本地 `htdemucs_6s` 分离 vocals / bass / piano / guitar / drums / other。使用同一增益处理，不分别归一化各声部。
5. 对原曲和六个声部计算 RMS、固定 −60…0 dBFS 能量映射及功率加权频谱重心。4096 点窗口，2205 点步长（20 帧/秒）；逐声道功率平均，避免反相立体声能量抵消。
6. Basic Pitch 的 ONNX 后端转写人声、低音、钢琴、吉他，保留音符起止、MIDI 音高、模型振幅分数。选择各声部较强的声道作为转写输入。鼓轨使用正向频谱通量提取瞬态起音，不宣称检测了节拍/BPM。
7. 前端轮询任务进度。完成后以播放器 `currentTime` 驱动同窗六轨，连续窗口显示过去 3 秒与未来 9 秒。四个有音高声部使用音符条，每轨音高范围由整曲决定，播放/跳转不改变音高位置；鼓用起音脉冲，other 用能量带（宽度为 −60…0 dBFS 映射，颜色随频谱重心变化）。共享播放线并向左滚动；关闭连续滚动后按 12 秒分页。
8. 可导出完整 JSON 和整曲音符/起音 PNG。原曲能量/重心收纳在可展开面板中。

六轨分析按事件的局部能量筛选弱音符和弱鼓点。弱音符与强轨的同音重叠、起音和能量变化一致时，标为疑似串音。页面可勾选「显示未确认事件」查看弱候选，导出的 JSON 也保留这些候选。other 表示未归类残余。鼓点强度在鼓轨内归一化，不用于跨曲比较。

## 后台任务与存储

- `GET /default`：默认曲目名称；`GET /default/result`：只读六轨缓存，缺失或过期返回 409，不排队分析。
- `GET /sample?playback=1`：轻量播放副本，支持 Range / HEAD / ETag；不带 playback 则返回原曲。以上接口支持会话 header 或查询参数 token。
- `POST /jobs`：原始音频 body，返回 202 和任务状态。
- `GET /jobs/{id}`：状态、阶段、进度、错误信息。
- `GET /jobs/{id}/result`：完成后的 JSON；未完成返回 409。
- `DELETE /jobs/{id}`：取消排队或运行中的任务。
- 任务接口均要求 `X-Hya-Token`。`/analyze` 保留快速分析接口。
- 一次运行一个模型任务，最多四个未完成任务。任务状态仅在当前进程内保存，最多保留 32 条；重启后重新导入可复用磁盘缓存。
- 默认曲目副本持久保存在 `outputs/default/`。其他原始上传和中间音频只存在任务临时目录，完成、失败或取消后清理。分析 JSON 保存在 `outputs/cache/`，包含音符与声学信息；退出后仍保留。需要清理时可删除此目录，下次重新分析。
- 本机手动导入的音频原件可放在 `inputs/`，然后在页面选择文件。`inputs/`、`outputs/`、`.venv/` 和 `.models/` 均不提交 Git。

## 项目结构

| 路径 | 职责 |
|---|---|
| `启动 Hya.command` / `app.py` | macOS 启动脚本和本机 HTTP 服务入口 |
| `precache.py` / `ml_pipeline.py` | 默认曲目预缓存命令和分轨分析工作进程入口 |

| `web/ui.html` | 播放、可视化、任务状态与导出 |
| `assets/` | 随仓库分发的背景与标准示范音频 |
| `tests/` | Python 回归、前端回归和可选的真实模型验收 |
| `docs/` | 音频工具说明、处理流程和历史验收截图 |
| `inputs/` | 本机导入的音频原件 |
| `outputs/` | 默认曲目副本、分析缓存、分轨和验收产物 |

## 验证

```sh
.venv/bin/python -m unittest discover -v
for test in tests/test_*.js; do node "$test" || exit 1; done
```

自动化检查信号、反相立体声、音符边界、鼓点时刻，以及任务鉴权、缓存、取消、失败/超时、绘图历史稳定性和界面状态恢复。

实际模型冒烟测试：

```sh
.venv/bin/python ml_pipeline.py /absolute/path/short.wav /tmp/hya-result.json
```

短合成音频只能验证流水线可运行；复杂音乐的分离/转写准确率仍需真实样本评估。处理流程见 [docs/processing-flow.md](docs/processing-flow.md)。

手机通过隧道访问时，默认曲目走只读 GET，不受上传大小限制。手动导入其他大文件仍受隧道上传上限约束；若通道返回 413，界面会提示在电脑上导入并预缓存，不再显示 JSON 解析异常。

## 月夜叠层视图

主界面采用月夜湖面背景、简洁播放器及同一画布上的六种声部颜色。右侧的绘制笔尖横坐标固定，只随音高上下运动；左侧保留最近 10 秒轨迹，历史随时间经过笔尖向左更新。六个声部共用音高坐标，没有分行。淡色 MIDI 方块保留音符的真实起止与音高；「更多」可关闭参考图，或展开原始六轨图与声学信息。

四个有音高声部复用缓存音符，通过动态规划选择整段旋律候选路径：音区、音符时长和音高衔接为主要依据，振幅仅提供较小权重。钢琴等声部偏向上声部，低音轨偏向下声部；切换只发生在新音起音处，允许休止，不在延音中途捡起伴奏。显示保留所选 MIDI 音高，不进行音高平滑或插值。原始音符不变，无需重新转写。这是启发式声部追踪，不保证等同于人工主旋律；内声部旋律、交叉声部与长踏板仍可能选错。鼓显示起音强度，其他声部显示能量，不将它们标为真实音高。无音符时断开曲线，钢琴独奏仍仅绘制钢琴，不人为补足六条线。

背景紫青光柱由 Web Audio AnalyserNode 的真实 FFT 频率数据驱动，横向为低频到高频。首次点击播放时初始化，同一个播放器只连接一次；暂停时不绘制频谱，不支持 Web Audio 时保留播放和已有分析。背景素材为用户提供的 `assets/moonlit-lake.jpg`，不依赖外部图床。

补充前端验证：`node tests/test_scene.js`（固定笔尖、共用音高坐标、六层叠加、暂停/跳转一致性、静音断线与独奏）。

旋律选择回归：`node tests/test_melody.js`。人工校准可先选 10–20 秒，记录每个主旋律音的起止秒数与 MIDI 音高（如 C4=60），休止明确标为空；用原始音符图核对，分别记录漏音和选错声部，避免用整曲听感代替逐段对照。

## 标准示范曲目与已知答案验收

在「更多设置 → 曲目」的「标准示范」组中，选择任一曲目即可载入：

- **纯净单音旋律**：9 秒正弦波，C5 D5 E5 G5 / E5 D5 C5 C5，含短休止、长休止与同音重复。
- **旋律与更响的低音伴奏**：同一旋律叠加低两八度的低音，伴奏振幅 0.32、旋律振幅 0.14，用于检查更响伴奏是否抢走旋律。

同一个下拉框也可切换回默认曲目或启动自由合成体验。标准示范的 WAV 和 Basic Pitch 实际输出随仓库保存在 `assets/demos/`，无需下载模型、上传或重新分析即可播放。参考旋律来自音频生成配方，独立存放于 `reference_melody`，不作为识别结果输入；页面列出起止秒数、预期 MIDI 音高和所选路径在音符中点的音高。

复现完整验收：`.venv/bin/python -m tests.test_synthetic_melody`。生成音频，运行真实 Basic Pitch ONNX，再调用页面中的真实旋律选择函数；结果写入 `outputs/validation/simple-melody/`。加 `--publish` 会在验收通过后更新仓库标准示范文件。

首次验收两段音频各有 72 个音符内部采样点，识别包含预期音高、旋律选择正确率均为 100%，休止采样正确率均为 100%。音符采样避开起音 150 ms 与结束前 120 ms，休止检查避开边界 150 ms；阈值为音高和休止正确率均不低于 95%。这不等于起止时间精确，也不是人类听感评测，更不能外推到真实钢琴、踏板延音或复杂复调。详细逐音数据见 `assets/demos/validation.json`。
