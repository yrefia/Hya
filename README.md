# Hya · 声音的形状

Python 驱动的本机图形应用。macOS 自带 afconvert 解码；无需 pip、Xcode、账号或联网服务。浏览器作为图形窗口，Python 负责 FFT 与声学分析。

## 启动

双击 `启动 Hya.command`。如果 Finder 未执行，请在终端运行：

```sh
cd /Users/lightscape/Projects/hya
python3 app.py
```

浏览器会自动打开。先点击「体验示例声音」，随后播放、暂停或拖动音频进度。关闭终端或 Control+C 停止服务。音频只发送给本机 127.0.0.1，分析临时文件在请求结束后删除。

## 功能

- 导入 WAV / MP3 / M4A / AIFF 等系统能解码的音频；最大 128 MB、10 分钟。
- 能量曲线、频谱重心、三频段统计与音高轨迹及确定性指纹参数。
- 浏览器播放及 currentTime 驱动的动态反馈；减少动态效果开关。
- 导出 JSON 参数、静态 PNG 图像；内置自行合成的合法示例。

## 算法与限制

v2：22050 Hz、单声道、16-bit PCM；2048 点 Hann 窗 FFT，1024 点步长；RMS 使用未加窗样本，dBFS 固定映射 −60…0 到 0…1。频谱重心为功率加权。0–250 / 250–2000 / 2000–11025 Hz 三频段；180 个时间段形成环形轮廓。没有随机视觉参数。RMS 不是 LUFS，也不是情绪识别。

原型单声道混合可能抵消反相立体声，后续应改成逐声道能量分析。不同编码、裁剪和跨设备重采样不保证相同指纹。浏览器格式支持与系统解码能力不同：AIFF 若无法播放，转换为 WAV。动画跟随播放器 currentTime，但蓝牙输出延迟未校准。特征为最近帧查找，未实现插值。

`audio_analysis.py` 是独立分析模块；`app.py` 是启动入口；`ui.html` 是图形界面。后续将分析模块迁移至 Swift。

## v2：旋律与伴随音高线

启动方式不变，请重启 Python 服务并刷新页面。最长 10 分钟、128 MB；2048 点 Hann 窗 FFT，1024 点步长。新增 `music_features.py`：频谱峰值、对数谱峰插值、明显泛音抑制、连续性偏好，得到一个主旋律候选和最多三个伴随音高。背景线来自频谱平坦度，并不表示独立环境声音轨。

金色线显示旋律候选，其余线显示按音高排序的伴随候选。纵向位置代表音高，移动窗口展示过去 7 秒及未来 3 秒，细小起伏由当前能量调节。暂停后画面固定、拖动可复现；关闭动态反馈后仍保留音高轨迹。JSON 包含每帧 voices（pitch 为 MIDI 半音值、strength、confidence）和 noise。PNG 导出全曲静态轨迹。

**能力边界**：此版本没有训练模型、没有真正的人声/乐器分离，也不识别乐器名称；较响的伴奏可能取代旋律，泛音抑制可能漏检真实和弦音，伴随候选排序不保证同一声部身份。confidence 是启发式分数而非校准概率。复杂音乐需要后续模型与真实样本评估，不能以本示例测试代替。旧 v1 在 Git `a9c7565` 保存。

验证：新增旋律+和弦混合信号测试、旋律变化测试及无声无音高测试。computer use 连接超时，尚未完成真实界面视觉验收。

## v3：固定历史轨迹与分轨显示

删除全部人为波动，历史点的纵坐标只由已分析音高决定，横坐标随播放时钟向左平移。默认显示两个独立轨道（旋律候选、低音伴随候选），相同 C2–C7 刻度，12 秒历史窗口，无未来轨迹；低置信度或大跳跃处断线。分析窗口扩大到 4096 点，时间戳改为窗口中心，过滤孤立的单帧跳变；这些改善不等于验证了真实主旋律识别准确率。

本地测试曲目可使用 `HYA_TEST_AUDIO='/absolute/path/song.mp3' python3 app.py` 启动，然后点「载入测试曲目」。不复制曲目到仓库；入口要求当前会话 token。默认启动未配置时仍使用「导入音频」。
